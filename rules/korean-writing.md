# 한국어 작성 규칙

모든 프로젝트의 한국어 텍스트에 적용한다. 문서와 코드 주석, 커밋 메시지, 사용자에게 보내는 응답이 대상이다. 저장소가 고유한 용어 규칙이나 문체 규약을 따로 가지면 그것이 여기에 더해지고, 어긋나면 저장소 쪽이 이긴다.

코드 식별자는 대상이 아니다. 변수와 타입, 함수 이름은 영어로 쓴다.

## 기호

가운뎃점과 화살표, em dash는 쓰지 않는다. 이모지도 쓰지 않는다.

나열은 조사와 쉼표로 푼다. 흐름은 문장으로 쓴다.

| 쓰지 않는 표기              | 대신 쓰는 표기                              |
| --------------------------- | ------------------------------------------- |
| lint·타입 검사·빌드         | lint와 타입 검사, 빌드                      |
| URL 파싱 → 상태 생성 → 요청 | URL을 읽어 상태를 만들고 그 상태로 요청한다 |
| 상태 동기화 ↔ 화면 갱신     | 상태를 동기화하면 화면이 갱신된다           |
| 완료 ✅                     | 완료                                        |

이 기호들은 사람이 손으로 글을 쓸 때 거의 나오지 않는다. 항목을 기계적으로 압축하거나 문장을 급히 이어 붙일 때 주로 등장한다. 상태나 강조는 텍스트 라벨로 표시한다.

### 손대지 않는 것

코드 블록 안의 `=>`, 다이어그램 문법의 `->>`, 마크다운 표 구분선 `---`은 문법이다. 그대로 둔다. 라이브러리와 제품 이름에 들어간 기호도 고치지 않는다.

**다만 코드 블록 안이라고 전부 문법은 아니다.** 테스트 이름이나 주석에 적힌 한국어 문장은 산문이다. `test("연결 요청 → 상태 업데이트", ...)`의 화살표는 문법이 아니므로 고친다.

## 한자

한자를 쓰지 않는다. 예외는 없다.

| 쓰지 않는 표기 | 대신 쓰는 표기              |
| -------------- | --------------------------- |
| 死 설정        | 죽은 설정, 쓰이지 않는 설정 |
| 前 버전        | 이전 버전                   |
| 約 3초         | 약 3초                      |

한자는 뜻을 한 글자로 압축하려 할 때 끼어든다. 압축하지 말고 말로 푼다. 커밋 메시지처럼 길이가 아쉬운 자리에서 특히 나오니 그 자리를 더 살핀다. 한 번 원격에 올라간 커밋 메시지는 고치지 못한다.

## 단어와 문장

행정 문서에서나 쓰는 한자어는 일상어로 바꾼다. 한글로 적힌 한자어를 말하며, 한자 자체는 위의 한자 절에서 금지한다.

같은 말을 두 번 하지 않는다. 앞 문장이 뒤 문장의 요약이면 앞 문장을 지운다. 지워도 잃는 것이 없다면 군더더기다.

자기 작업을 스스로 평가하지 않는다. 숨은 난이도가 여기 있다거나 설계가 성공했다는 증거라는 식의 문장은 읽는 사람이 판단할 몫을 글쓴이가 미리 가져간다. 사실만 적고 판단은 맡긴다.

`~가 아니라 ~이다` 구문을 남발하지 않는다. 한 문장에 두 가지를 욱여넣어 호흡이 길어진다. 두 문장으로 세우면 둘 다 또렷해진다.

명사를 이어 붙여 압축하지 않는다. "화면 무관 동일 동작"처럼 명사를 다섯 개 붙이면 읽는 사람이 속으로 풀어야 한다. "어느 화면에서나 똑같이 동작한다는 보장"으로 쓴다.

불필요한 진행형과 명사화를 없앤다.

| 고치기 전         | 고친 뒤               |
| ----------------- | --------------------- |
| 보장하고 있습니다 | 보장합니다            |
| 통과를 확인합니다 | 통과하는지 확인합니다 |
| 시나리오의 측정   | 시나리오에서 잰 값    |

영어 직역을 걷어낸다. "공백을 닫다"는 close the gap의 직역이니 "공백을 메우다"로 바꾼다. "~하게 합니다"는 make 구문의 흔적이다. "~하지 않아도 됩니다"로 쓴다.

## 금지 표현 목록

지적을 받고도 다시 새어 들어오는 말들이다. 사람의 주의로는 막히지 않아서 목록으로 둔다. 새 위반이 잡히면 이 목록에 추가한다.

| 종류 | 쓰지 않는 말 | 대신 |
| --- | --- | --- |
| 결산 피벗 | 따라서, 결론적으로, 이를 통해로 문단 닫기 | 사실이나 다음에 할 일로 닫는다 |
| 메타 담화 | 앞서 설명했듯이, 이제 알아보겠습니다, 살펴보겠습니다, 아시다시피, 적어둘게요, 눈여겨봐주세요 | 적을 것을 적겠다고 예고하지 않고 바로 적는다 |
| 주체 없는 사건 서술 | 제보가 왔습니다, 문의가 왔습니다, 요구가 들어왔습니다 | 누가 무엇을 했는지 적는다. "PM이 물었습니다" |
| 행동을 요약하는 추상 서술 | 조건을 좁혀보니, 원인을 추적하니, 파고들어 보니 | 실제로 한 일과 본 것을 적는다 |
| 경구로 문단 닫기 | 격언 모양 문장으로 맺기, "~하기 위한 장치입니다" | 그 자리에서 실제로 하는 일로 푼다 |
| 추정어로 수치 정당화 | 보통, 통상적인, 대부분, 일반적으로 | 출처를 달거나 삭제 |
| 출처를 가리키는 척 | 공식 공지에 따르면, 알려진 문제가 있습니다, 잘 알려져 있듯이, 교과서대로면, 정석대로면, 원칙적으로는 | 문서 이름과 링크를 그 자리에 적거나 주장을 뺀다. 근거가 바로 뒤에 있으면 권위를 지우고 근거만 남긴다 |
| 목록을 번호로 되돌아보기 | 두 번째는, 첫 번째 이유는 | 항목 안에 넣거나 내용을 다시 적는다 |
| 의인화 | 마음 놓고, 똑똑하게, 알아서 척척, 어디서 아픈지 | 무엇이 느려지고 무엇이 실패하는지 적는다 |
| 자기 평가 | 제일 중요한 판단입니다, 하이라이트입니다, 우아하게, 성공적으로 | 사실로 바꾼다 |
| 판단을 미리 단정 | 이유는 분명해요, 기준은 간단해요, 훨씬 명확합니다 | 근거만 남긴다. 분명한지는 읽고 나서 독자가 정한다 |
| `~한 셈입니다` | 네 개를 다시 그린 셈입니다, 선언하는 셈이에요 | 그냥 "네 개를 다시 그렸습니다" |
| 값어치를 말하는 추상 표현 | 쓸모가 있다, 값어치가 있다, 의미가 있다, 값을 한다 | 무엇에 쓰는지 바로 적는다 |
| 책임을 에두르는 말 | 개발자 몫이 됩니다, 사용자 몫으로 남습니다, ~에게 달려 있습니다 | 누가 무엇을 해야 하는지 그대로 적는다 |
| 크기 수식어 | 대폭, 획기적, 크게 | 숫자가 크기를 말하게 한다 |
| 한자어 허사 | ~작업을 수행합니다, ~진행합니다, ~실시합니다, 돌파구 | 동사로 되돌린다 |
| 번역체 명사 나열 | 인증 처리가 완료된 후, ~을 통해 | 사용자를 인증한 후, ~로 |
| 업계 은어 직역 | 던진다(throw), 찌른다, 태운다 | 예외를 일으킵니다, 요청을 보냅니다 |
| 기계적 나열 | 첫째 둘째 셋째, 3박자 나열, "단순한 ~이 아닙니다" 남발 | 문장으로 푼다 |
| 프랙탈 요약 | 도입에서 요약하고 절마다 소결하고 마무리에서 또 요약 | 한 번만 한다 |
| 무조건 긍정 마무리 | 갈등을 서둘러 조화로 닫기, 양비론 봉합 | 트레이드오프와 안 풀린 문제를 그대로 남긴다 |
| 신입형 소감 | 많이 배웠다, 성장했다, 영감을 줬다, 인상 깊었다 | 무엇을 알게 됐고 그래서 무엇을 바꿨는지 적는다. 무엇에서 받아 무엇이 나왔는지가 같이 적혀 있으면 통과 |
| 효과를 뭉뚱그리는 관용구 | 잘 듣는다, 먹힌다, 통한다, 효자다, 한몫한다 | 무엇이 무엇에 얼마나 작용하는지 적는다 |
| 뜻을 압축한 추상 명사 | 갈래, 층위, 결, 축 (나뉘는 대상이 안 적힌 채) | 나뉘는 것의 이름을 그 자리에 적는다 |
| 비유로 쓰는 셈 단위와 장소 | 코드가 세 벌, 규칙 한 벌, 맞는 자리는 | 세 곳에 구현, 쓸 만한 경우 |
| 의존을 물건에 빗대는 말 | 전부 매달려 있다, 통째로 얹혀 있다, 어깨에 지운다 | 무엇이 멈추면 무엇이 멈추는지 적는다 |
| 낯선 한자어와 문어체 | 되풀이, 견주다, 떠받치다, 가늠하다 | 반복, 비교하다처럼 평범한 말로 |
| 사과와 방어 | 부족한 글이지만, 틀린 부분이 있으면 알려주세요 | 쓰지 않는다 |

## 비유와 번역 은유

평범한 말이 이미 있으면 비유를 쓰지 않는다. 영어 기술 용어를 한국어로 옮긴 은유(봉투, 배선, 기술 부채, 행복 경로 같은 것)도 쓰지 않는다. 원어를 모르는 사람이 그 한국어만 보고 뜻을 짐작할 수 없으면 위반이다. 판정 순서와 대응표는 `korean-writing-review.md`의 비유 절과 번역 은유 절에 있고 문서를 쓸 때 함께 실린다.

## 쉼표

연결어미 뒤의 쉼표는 대부분 군더더기다. `~하고,` `~지만,` `~어서,` 뒤에 붙은 쉼표는 지우고 읽어본다.

"다시 조회하고, 그래서 복원되지 않습니다"는 "다시 조회해서 복원되지 않습니다"가 낫다.

다만 기계적으로 걷어내면 안 된다. 주어가 서로 다른 긴 절 두 개를 잇는 자리에서는 쉼표가 있어야 절 경계가 보인다. 규칙이 언어를 이기면 오히려 읽기 나빠진다. 한 문서에서 열 건 넘게 걸리더라도 전수로 확인하고 하나씩 판단한다.

## 참조

번호로 다른 문서나 항목을 가리키지 않는다. "[2]의 URL 파싱 층", "보장 3 충족" 같은 표기는 읽는 사람을 목록으로 되돌려 보낸다. 문서 이름으로 부르거나 내용을 그 자리에 다시 적는다.

"전자는", "후자는"도 같은 이유로 쓰지 않는다. 읽는 사람을 앞 문장으로 되돌린다.

같은 이유로 문서 안에서 다른 문서로 보내는 링크도 최소화한다. 바로 위에 이미 답이 있는데 상세는 저쪽을 보라고 하면 읽던 흐름이 끊긴다. 목차나 상세 자료로 안내하는 링크는 목적이 분명하니 남긴다.

## 목록과 산문

목록이 산문을 대체하지 않게 한다. 목록 항목 수가 산문 문단 수에 가까워지면 글이 아니라 발표 자료가 된다.

특히 **한 문장이 목록을 사이에 끼고 두 동강 나는 배치**를 쓰지 않는다. 사람이 쓴 글에서는 거의 나오지 않는 모양이다.

```
이렇게 하니
- 각 매니저는 자기 책임에 집중
- 매니저끼리는 인터페이스로만 소통
하게 되었습니다
```

목록을 빼면 "이렇게 하니 하게 되었습니다"가 된다. 서술어가 목록 너머에 혼자 남았다. 한 문장으로 푼다.

같은 계열로 둘을 더 본다. **목록을 여는 문장은 마침표로 닫는다.** 서술어 없이 "이 구조의 장점"처럼 조각으로 목록을 열지 않는다. 그리고 **한 목록 안에서 항목 종결을 통일한다.** `~없다`와 `~늘어남`과 명사형이 섞이지 않게 한다.

글을 고치고 검사할 때의 절차는 `korean-writing-review.md` 에 있다. 마크다운 파일을 열면 함께 실린다.

## 마지막 기준

이 규칙들은 전부 하나에서 나온다. 읽는 주체는 사람이다. 어떤 문장이 규칙에 걸리는지 애매할 때는 그 문장을 소리 내어 읽었을 때 사람이 말하는 것처럼 들리는지 물으면 된다.
