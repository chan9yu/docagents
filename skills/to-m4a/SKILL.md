# to-m4a

녹화 영상에서 음성만 뽑아 클로바노트용 `.m4a`를 만든다. 변환은 전부 `scripts/to-m4a.sh`가 하고 매번 같은 결과를 낸다. 이 문서는 스크립트를 어떻게 부르고 출력을 어떻게 읽어 보고하는지 적는다.

## 돌리는 법

```bash
bash ~/.agents/skills/to-m4a/scripts/to-m4a.sh "<녹화 파일 경로>"
```

- 출력은 입력 옆에 같은 이름의 `.m4a`다. 이미 있으면 스크립트가 멈춘다. 그때는 사용자에게 알리고 `-o <다른 경로>`로 다시 돌리거나 기존 파일을 어떻게 할지 묻는다. 덮어쓰기는 스크립트가 하지 않으니 기존 파일을 임의로 지우지 않는다
- 180분이 넘으면 `이름-1.m4a`, `이름-2.m4a`로 나눈다. 클로바노트가 한 파일에 180분까지만 받기 때문이다. 자르는 자리는 경계 앞 60초 안에서 가장 조용한 초라 말 중간이 잘리지 않는다. 한도는 `--max-minutes`로 바꿀 수 있다
- 파일이 여럿이면 파일마다 한 번씩 부른다. 서로 의존이 없으니 한 응답에서 병렬로 부를 수 있다
- macOS 화면 기록의 기본 이름에는 공백이 있다. 경로는 항상 따옴표로 감싼다

스크립트가 하는 일은 넷이다. afconvert로 PCM 16kHz WAV로 풀고, 채널별 음량을 재서 소리 있는 채널만 모노로 섞고, AAC 48kbps로 인코딩하고, 결과를 다시 디코드해 길이와 음량을 확인한다. 임시 파일은 실패해도 지워진다. 2GB 영상이 1분 안에 끝난다.

## 왜 이렇게 하나

- 16kHz 모노 48kbps로 줄이는 이유. 음성 인식 모델이 그 이상을 쓰지 않는다. 2GB 영상이 10MB대가 되고 인식 품질은 같다
- 채널을 고르는 이유. macOS 화면 기록은 출력 장치의 채널 수를 따라가 7.1 트랙이 생기고 소리는 한 채널에만 있다. 표준 다운믹스는 채널마다 다른 계수를 곱하므로 소리가 어느 채널에 있느냐에 따라 음량이 달라진다. 가장 큰 채널 기준 20dB 안에 드는 채널만 평균하면 그 변수가 사라진다
- PCM으로 먼저 푸는 이유. afconvert가 8채널 AAC를 바로 모노로 바꾸는 것을 거부한다(`cclo` 오류)
- 피크를 -1dBFS로 맞추는 이유. 녹화 피크가 0dBFS에 닿아 있는 경우가 대부분이라 1dB 낮추고, 반대로 작은 녹음은 최대 20dB까지 키운다

## 출력을 읽고 보고하는 법

스크립트 출력에서 사용자에게 옮길 것은 셋이다.

1. 결과 표. 원본과 결과의 크기와 길이, 영상 제거, 오디오 형식 변화를 표 하나로 보인다. 원본은 지우지 않았다고 적는다
2. 채널 분석 해석. 채널 표를 그대로 붙이지 말고 한 문장으로 푼다. "8채널 중 0번에만 소리가 있어 그것만 살렸다", "좌우가 같은 소리라 합쳐도 잃는 것이 없다"처럼. 섞은 채널끼리 RMS가 3dB 넘게 다르면 마이크와 시스템 오디오처럼 다른 소리가 섞인 것일 수 있으니 그 사실을 알린다
3. 마지막 확인 줄. 길이가 원본과 같은지, 소리 있는 초 비율이 채널 분석과 비슷한지 본다. 크게 다르면 변환이 잘못된 것이니 결과를 믿지 말고 원인을 본다

나뉜 파일이면 조각마다 길이를 적고 클로바노트에 순서대로 올리라고 알린다.

## 스크립트가 멈추는 경우

| 메시지 | 뜻 | 할 일 |
| --- | --- | --- |
| 이미 있다 | 출력 파일이 있다 | 사용자에게 묻는다. 덮어쓰기는 스크립트가 하지 않는다 |
| 오디오 트랙을 읽지 못했다 | 소리 없는 녹화이거나 지원하지 않는 형식 | 사용자에게 알린다. ffmpeg가 있으면 그쪽으로 시도할 수 있다 |
| 모든 채널이 무음이다 | 트랙은 있지만 비어 있다 | 녹화 설정에서 마이크가 빠졌을 가능성이 크다고 알린다 |
| numpy가 없다 | python3에 numpy가 없다 | `which python3`로 어느 python3가 잡혔는지 본다. Xcode의 python3에는 있다 |

## 의존성

macOS 내장 `afconvert`와 `afinfo`, `python3`와 numpy다. ffmpeg는 필요 없다. 다른 OS에서는 돌지 않는다.
