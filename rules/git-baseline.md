# Git 워크플로우

## 커밋 메시지

형식은 프로젝트가 정한다. 형식이 없으면 Conventional Commits를 쓴다.

body는 **왜**를 쓴다. 무엇을 바꿨는지는 diff에 있다.

## 커밋 분할

한 작업이 하나 이상의 원자 커밋이 된다. 나누는 기준은 셋이다.

- 타입 정의, 구현, 테스트, 문서를 각각 별도 커밋으로
- 리팩토링과 기능 추가를 섞지 않는다
- 각 커밋은 빌드와 테스트가 통과하는 상태여야 한다

## 브랜치

기본 브랜치에 직접 커밋하지 않는다. 작업 단위마다 브랜치를 딴다.

## 커밋 전 확인

포맷터를 pre-commit 훅으로 돌리는 저장소에는 함정이 있다.

**한 파일에 스테이징된 변경과 스테이징되지 않은 변경이 함께 있으면(`git status`의 MM) 훅 처리 중 unstaged 변경이 유실될 수 있다.**

```bash
git status --short     # MM으로 시작하는 줄을 먼저 확인
```

MM 파일이 있으면 커밋 전에 정리한다. 커밋 후에는 `git status`를 다시 대조해 의도한 것만 들어갔는지 확인한다.

## 강제 푸시

- `--force` 기본 금지
- 리베이스가 필요하면 `--force-with-lease`만
- 기본 브랜치에 force는 금지

## 금지 패턴

1. `git add -A` 광범위 스테이징: 파일 단위로 명시한다
2. `.env`와 비밀값 파일 커밋
3. 충돌을 `--ours`로 일방 해소: 의미를 검토하고 해소한다
4. "WIP" 커밋을 그대로 병합
