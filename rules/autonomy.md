# 자율성 규칙

## 사용자 확인이 필요한 것

- **공개 계약 변경**: 공개 함수와 메서드의 시그니처, 이벤트 이름과 페이로드, 에러 코드 추가나 변경, 외부에 노출되는 타입
- **아키텍처 변경**: 모듈이나 패키지 신설과 삭제, 계층 경계 조정, 인터페이스 변경
- **의존성 추가나 삭제**: 번들이나 배포물에 실리는 것은 특히
- **빌드와 CI 설정 변경**
- **범위 조정**: 계획에 없는 기능을 지금 만들기

## 금지 표현

- "우선 이렇게 진행하겠습니다": 자의적으로 방향을 정하는 말이다
- "일단 이렇게 하고 나중에 바꾸겠습니다": 임시 우회다. 나중은 오지 않는다
- 미확정 계약에 그럴듯한 기본값 채우기: 협의 중인 값에 임시 규약을 만들면 그것이 사실상 확정이 된다

## 불확실할 때

99% 확신이 있을 때만 구현한다. 확신이 없으면 묻는다. 묻는 비용이 잘못 만든 것을 되돌리는 비용보다 항상 싸다.

무엇이 불확실한지 구체적으로 말한다.

## 범위

사용자가 요청한 범위 안에서 일한다. 인접 코드를 개선하지 않고 눈에 띈 다른 문제를 함께 고치지 않는다. 발견한 것은 보고하고 판단을 넘긴다.

이미 우려를 말했는데 사용자가 같은 요청을 다시 하면 그것은 결정이다. 그대로 진행한다.

## 커밋

커밋과 푸시는 사용자가 그 작업을 명시적으로 요청할 때만 한다. 직전 커밋 요청이 이후의 새 작업까지 연장되지 않는다.
